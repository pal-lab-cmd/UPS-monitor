# UPS Monitor

*[English](README_en.md)*

DIY-моніторинг саморобного UPS на базі ESP32-S3 та INA3221. Вимірює напругу/струм/потужність на трьох каналах (вхід від мережі, вихід на навантаження, батарея), віддає дані по мережі як **Network UPS (протокол NUT)** — сумісний, зокрема, з QNAP QTS ("Network UPS slave") — і надає простий веб-інтерфейс для моніторингу та налаштувань.

## Апаратна частина

- ESP32-S3 (N16R8 або сумісний), I2C на GPIO8 (SDA) / GPIO9 (SCL)
- INA3221 — 3-канальний монітор напруги/струму, адреса `0x40` (A0 → GND)
- GPIO4 — Power-Valid (`PV`) вихід INA3221, апаратний тригер пробудження з deep sleep (зовнішній pull-up R21 10K до VS на платі; див. розділ «Сон» нижче)
- Заводські шунти R100 доповнені паралельно допаяними R010 (~9 мОм ефективно на канал)
- Канали (мітки задаються в `config.h`, зараз): `Battery`, `PSU in`, `UPS out`

## Вимоги (бібліотеки)

Встановлюються через Arduino Library Manager:

Плата: `ESP32S3 Dev Module`, PSRAM: `OPI PSRAM`, Flash Size: `16MB`.

## Функціонал

- Читання 3 каналів INA3221 (напруга шини, напруга шунта, струм, потужність) з калібруванням опору шунта та офсету нуля окремо на кожен канал, а також з корекцією полярності шунта (`config.h → CH_CAL`, поле `currentSign`) — так, щоб знак струму завжди відповідав фізичному змісту (для батареї: `+` зарядка / `-` розряд; для входу від мережі та виходу на навантаження — завжди невід'ємний, бо це однонаправлені канали)
- Дедбенд для струму (`CURRENT_DEADBAND_MA`) — прибирає фантомний струм від офсету на знеструмлених/непідключених каналах
- Оцінка заряду батареї (SOC%) через **coulomb counting** — інтегрування струму батареї в часі, з IR-компенсацією просідання напруги під навантаженням (`BATTERY_INTERNAL_RESISTANCE_OHM`) та самокалібруванням по двох реперних точках напруги (SOC 100%/0%): при досягненні напруги "повна" лічильник скидається на 100%, при досягненні напруги "порожня" — на 0%, і заразом повільно підлаштовується збережена повна ємність батареї під реально спостережену ємність останнього циклу розряду (враховує деградацію з часом)
- Кеш показань, що оновлюється раз на секунду (`SAMPLE_INTERVAL_MS`) в `loop()` — і HTTP, і NUT читають лише з нього, щоб не звертатись до I2C паралельно з різних async-контекстів
- Веб-інтерфейс (`/`) — таблиця напруга/струм/потужність по каналах з SOC% батареї та % навантаження UPS-виходу прямо в назві рядка, оновлення раз на секунду, перемикач мови **UA/EN**
- Історія показань і графіки (`/history`) — дворівневий кільцевий буфер на FFat (`history.h`): "detail" — 1 запис/хв за останні `HISTORY_DETAIL_DAYS` (4) дні, "long" — 1 запис/15 хв за весь термін зберігання (жорсткий кап `HISTORY_RETENTION_DAYS_MAX` = 365 днів); файли фіксованого розміру, що самі перезаписують найстаріші записи по колу, тож місце на флеші не росте необмежено. Термін зберігання, обраний у `/settings/history`, лише відсікає видачу при читанні, не змінюючи розмір файлів. Рівень деталізації для конкретного запиту графіка обирається сервером автоматично; проріджування (stride) віддає приблизно бажану кількість точок незалежно від фактичної роздільності зберігання
- Розділ Settings (`/settings`) — WiFi, пароль доступу, дата й час (NTP-сервер, часовий пояс: випадаючий список поширених міст або ручне поле для POSIX TZ), калібрування батареї (ємність, напруги SOC 100%/0%), термін зберігання історії
- WiFi: збереження credentials у `Preferences`, автопідключення при старті (до 5 хв спроб), запасний AP-режим для первинного налаштування, ненав'язливе перепідключення в `loop()` при втраті зв'язку
- OTA-оновлення прошивки через `/update` (ElegantOTA)
- NUT-сервер (порт 3493) для інтеграції з NAS/іншими системами моніторингу UPS
- Єдиний пароль доступу (логін завжди `admin`) для розділу Settings, перезавантаження та OTA; змінюється через UI
- Factory reset фізичною кнопкою BOOT
- Deep sleep при простої (`sleep.h`) — засинає, коли немає напруги ні на `PSU in`, ні на `UPS out`, протягом `SLEEP_DEBOUNCE_MS`; прокидається апаратно (Power-Valid INA3221) або підстрахувально по таймеру — див. розділ «Сон» нижче

## Перший запуск

1. Прошити плату (Arduino IDE, `ESP32S3 Dev Module`)
2. Підключитись до точки доступу **`UPS-Monitor-Setup`**, пароль **`12345678`**
3. Відкрити `http://192.168.4.1/`, ввести SSID/пароль домашньої мережі
4. Пристрій перезавантажиться і підключиться до вказаної мережі
5. Змінити дефолтний пароль доступу через `/settings/password` (розділ Settings → "Пароль доступу") — за замовчуванням `change-me`, вказаний у `config.h → AUTH_DEFAULT_PASS`

## NUT-сервер (Network UPS Tools)

- Порт: **3493** (стандартний для NUT)
- Ім'я UPS: `esp32ups` (`config.h → NUT_UPS_NAME`)
- Другий, "дзеркальний" UPS-пристрій на тому самому сервері/порту: `qnapups` (`config.h → NUT_UPS_NAME_QNAP`) — ті самі показання під іменем, яке жорстко вшите в QNAP QTS (External Device → UPS → Network UPS slave) і не редагується в його GUI. Реальний QNAP-клієнт (`upsutil`) взагалі не шле `USERNAME`/`PASSWORD`/`LOGIN` — одразу після підключення виконує `LIST VAR`/`GET VAR`, тож окремих креденшлів для `qnapups` немає: доступ для нього read-only не через пароль, а структурно (сервер не реалізує `SET`/`INSTCMD` для жодного з пристроїв)
- Підтримані команди: `USERNAME`, `PASSWORD`, `LOGIN`, `LOGOUT`, `PRIMARY`/`MASTER`, `STARTTLS` (коректна відмова), `VER`, `NETVER`, `LIST UPS/VAR/RW/CMD/CLIENT`, `GET VAR/TYPE/DESC/UPSDESC/NUMLOGINS`
- **Автентифікація не обов'язкова для читання** — `LIST VAR`/`GET VAR` не вимагають попереднього логіну. Це навмисно: QNAP QTS (розділ External Device → UPS → Network UPS slave) не має полів логіну/пароля в принципі, лише IP-адресу сервера — тож для сумісності з ним читання лишається відкритим у локальній мережі
- `NUT_PASS` перевіряється лише якщо клієнт сам надсилає команду `PASSWORD` (наприклад, `upsmon` на Linux)

### Змінні, які віддає сервер

| Змінна | Джерело |
|---|---|
| `device.type`, `device.mfr`/`ups.mfr`, `ups.model`, `ups.firmware` | статичні |
| `ups.status` | `OL`/`OB` за напругою на каналі `PSU in` (поріг `INPUT_PRESENT_V`); `LB` додається, коли SOC батареї < `LOW_BATTERY_SOC_PERCENT`; `CHRG`/`DISCHRG` — за знаком струму батареї |
| `battery.voltage`, `battery.current` | канал `Battery` (струм зі знаком: `+` зарядка, `-` розряд) |
| `battery.charge` | **coulomb counting** — інтегрування струму в часі з IR-компенсацією та самокалібруванням по напругах SOC 100%/0% (див. Функціонал) |
| `battery.runtime` | оцінка часу роботи від батареї в секундах — лише під час реального розряду (`0`, якщо на мережі або струм у деадбенді), рахується з поточного стану заряду (мАг) і миттєвого струму |
| `input.voltage` | канал `PSU in` |
| `output.voltage`, `output.current` | канал `UPS out` (струм — завжди невід'ємний) |
| `ups.power`/`ups.realpower`, `ups.load` | розраховуються з каналу `UPS out`, `ups.load` — % від `UPS_RATED_POWER_W` |

## Калібрування INA3221

Окремий скетч `ina3221_test.ino` — для повторного калібрування після заміни/переприпаювання шунтів. Методика: подати на канал два різних відомих струми (звірені мультиметром послідовно в розриві кола), розв'язати систему `V = offset + I·R` для визначення `rShunt_mOhm` та `offset_mV`, підставити значення в `config.h → CH_CAL`. Одноточкове калібрування (лише за одним відомим струмом) дає помітну похибку на малих струмах — саме тому модель двопараметрична (нахил + офсет), а не проста пропорція.

Крім опору й офсету, кожен канал має поле `currentSign` (`+1`/`-1`) — компенсує полярність підключення шунта, щоб знак струму завжди відповідав фізичному змісту (для `Battery`: `+` зарядка / `-` розряд; для `PSU in` і `UPS out` струм завжди виводиться невід'ємним, бо обидва канали фізично однонаправлені). Перевіряється емпірично: підключити PSU при частково розрядженій батареї і подивитись знак `battery.current` — якщо він від'ємний під час зарядки, поміняти `currentSign` каналу `Battery` на `-1`.

`BATTERY_INTERNAL_RESISTANCE_OHM` (внутрішній опір пакета) впливає на точність IR-компенсації напруги при оцінці SOC — стартове наближення варто уточнити емпірично: прикласти відоме навантаження і виміряти `ΔV/ΔI`.

## Сон (deep sleep) при відсутності живлення

Плата живиться від акумулятора через окремий DC-DC-модуль незалежно від `PSU in`/`UPS out`, тож ESP32 продовжує працювати, навіть коли обидва канали "мертві". Саме цей стан — умова для сну заради акумулятора: система свідомо простоює (зберігання, від'єднане навантаження).

- **Умова засинання:** напруга на `PSU in` **і** на `UPS out` одночасно нижче `SLEEP_VOLTAGE_THRESHOLD_V` (за замовч. 2В), безперервно протягом `SLEEP_DEBOUNCE_MS` (2 хв — захист від флапання на короткочасних перехідних процесах)
- **Пробудження — два джерела одразу:**
  - **Апаратне, швидке** — Power-Valid пін INA3221 (`PV`, GPIO4). Важливо: PV апаратно працює як `AND` по всіх трьох каналах одночасно (Upper/Lower-Limit — єдина пара регістрів на весь чип, не per-channel), тож реально спрацьовує лише коли `PSU in` **і** `UPS out` повертаються практично одночасно (`Battery` завжди вище порогу, бо сама живить плату)
  - **Програмне, підстрахувальне** — періодичне пробудження по таймеру (`SLEEP_TIMER_RECHECK_US`, за замовч. 3 хв), яке й реалізує справжню `АБО`-логіку: якщо, наприклад, `PSU in` повернувся, а `UPS out` — ще ні (користувач лише підзаряджає, не вмикаючи навантаження), апаратний PV не спрацює, і саме таймер прокинеться сам і побачить зміну
- **Швидкий шлях без WiFi:** якщо пробудження підстрахувальне (по таймеру) і умова "немає напруги" й досі виконується — пристрій одразу засинає знову, **не піднімаючи WiFi/сервер узагалі** (лише I2C-перевірка, частки секунди на низькому струмі) — інакше кожен такий "просто перевірити" цикл коштував би стільки ж заряду, скільки повний WiFi-конект
- Перед сном форсовано зберігається стан coulomb-каунтера (`saveCoulombState()`) — deep sleep для чипа рівнозначний повній перезагрузці, RAM не зберігається (крім `RTC_DATA_ATTR`); історія цього не потребує, бо кожен запис і так синхронно флешиться одразу в `history.h`
- Пороги Power-Valid (`SLEEP_PV_UPPER_V`/`SLEEP_PV_LOWER_V`) записуються в INA3221 при кожному старті (`sleepSetupPowerValid()`) — потребують зовнішнього pull-up на лінії PV (на цій платі є, R21 10K до VS)
- Причина кожного пробудження логується в Serial (`sleepLogWakeReason()`): звичайний старт / апаратний PV / таймер
- Поки пристрій спить — він недоступний по HTTP/NUT, і в історії показань за цей період буде прогалина (очікувано: монітору нема що моніторити, поки система не живиться)

## Безпека

- **Живлення:** не підключайте USB одночасно із зовнішнім живленням від DC-DC модуля — обидва джерела намагатимуться видати 3,3В на той самий пін, що може пошкодити бортовий регулятор
- **Скидання пароля:** затиснути кнопку **BOOT** на 5+ секунд під час старту (Reset → тримати BOOT) — скидає WiFi-credentials і пароль доступу до заводських значень. Навмисно немає жодного механізму відновлення пароля через мережу — це вимагало б вбудованого "backdoor", що є неприйнятним компромісом безпеки для пристрою в домашній мережі
- Перед реальним розгортанням обов'язково змінити дефолтні значення в `config.h`: `AP_PASS`, `AUTH_DEFAULT_PASS`, `NUT_PASS`

## Плани / відомі обмеження

- Лічильник "скільки віддано з моменту останньої повної зарядки" (для самокалібрування ємності батареї при coulomb counting) живе лише в RAM — якщо пристрій перезавантажиться між реперними точками SOC100/SOC0, навчання ємності для цього конкретного циклу розряду втратиться (сам стан заряду при цьому не постраждає, він персистентний)
- `NUT_PASS` поки задається лише в `config.h`, не через UI (на відміну від `AUTH_DEFAULT_PASS`)
- Немає інстант-команд NUT (`LIST CMD` завжди порожній) — керування (наприклад, тестовий розряд) не реалізовано
